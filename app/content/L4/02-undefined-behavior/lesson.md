# 未定義行為與靜態分析

前 24 節的錯誤都有明確後果：編譯失敗、測試失敗、洩漏、崩潰。
這一節講一種**沒有明確後果**的錯誤 —— 它可能什麼都不發生，也可能在客戶的機器上才發生。

## 三種「標準沒說清楚」的行為

| 種類 | 意思 | 例子 |
|---|---|---|
| **實作定義** | 實作必須選一個行為並記錄 | `char` 是否有號、`>>` 對負數 |
| **未指定** | 實作可以任選，而且不必記錄 | 函式引數的求值順序 |
| **未定義行為（UB）** | 標準完全不規定，編譯器可以做任何事 | 有號整數溢位、越界存取、讀未初始化變數 |

大部分人把 UB 想成「會得到奇怪的結果」。實際更糟：

```cpp
int f(int x) { return x + 1 > x; }   // 編譯器可以回傳 true 常數
```

因為**有號溢位是 UB**，編譯器有權假設「`x + 1` 不會溢位」，於是 `x + 1 > x` 恆真。
`INT_MAX` 傳進去，它回傳 `true` —— 而且這不是 bug，是編譯器依法行事。

## 有號 vs 無號

```cpp
int  a = INT_MAX;  a + 1;    // ❌ UB
unsigned b = UINT_MAX; b + 1u;  // ✅ 定義良好，結果是 0
```

無號整數的算術被規定為模 2^N，所以溢位是**可預測的回繞**。這也是為什麼雜湊函式常用 `unsigned`。

## 中點：一個經典的 UB 題

```cpp
int midpoint(int a, int b) { return (a + b) / 2; }             // ❌ 一相加就溢位
int midpoint(int a, int b) { return a + (b - a) / 2; }          // ⚠ 對 INT_MIN/INT_MAX 仍溢位
int midpoint(int a, int b) {                                     // ✅
  return static_cast<int>((static_cast<long long>(a) + b) / 2);
}
```

三種寫法在**小數字上都正確**，只有第三種對所有 `int` 都安全。這就是 UB 的特性：
錯誤不會在測試的小資料上出現。

## 加寬，而不是「先算再檢查」

```cpp
if (a + b < 0) { ... }   // ❌ 判斷之前就已經 UB 了
```

UB 連「事後檢查」都不可靠 —— 檢查的那一行本身已經是 UB。
正確做法是**在運算前就加寬**：`long long sum = static_cast<long long>(a) + b;`。

## 靜態分析：`-fanalyzer`

本節的評測會多跑一個 grader：

```
g++ -fanalyzer -Wall -Wextra -c submission.cpp
```

它做跨函式的路徑分析。以下是**在這台機器上實測**它抓得到與抓不到的東西：

| 抓得到 | CWE |
|---|---|
| 記憶體洩漏 | CWE-401 |
| 空指標解參考 | CWE-476 |
| 使用未初始化的值 | CWE-457 |
| 陣列越界讀取 | CWE-126 |

| 抓不到 |
|---|
| **有號整數溢位**（本節的 `midpoint`，它沒有任何警告） |
| 除以零（常數情況） |

這張表本身就是重點：**工具的能力有邊界**。

所以本節有五個函式、五種問題，會由**不同的機制**抓到：

- `midpoint` 的溢位 → 只有**測試**會發現（分析器看不到）
- `first_of` 的洩漏 → 測試**完全正常**，靠**分析器**與**洩漏檢查**抓
- `clamp_byte` 的沒夾住 → 測試
- `safe_at` 的例外 → 測試

「測試全過」不代表沒問題；「分析器沒警告」也不代表正確。兩者都要，而且都只是防線的一部分。

## 你要實作的部分

```cpp
int midpoint(int a, int b);                                  // 不得溢位
std::optional<int> safe_at(const std::vector<int>& v, std::size_t i);  // 越界回 nullopt
unsigned char clamp_byte(int x);                             // 夾到 [0, 255]
```

起始碼三個地方漏了：`midpoint` 先相加再除（溢位）、`clamp_byte` 直接轉型沒有夾住
（負數會變成 255 附近的大數）、`safe_at` 用 `v.at()`（越界拋例外，介面要求回 `nullopt`）。
還有一個 `first_of`：測試完全正常，但每次呼叫都洩漏一塊記憶體。

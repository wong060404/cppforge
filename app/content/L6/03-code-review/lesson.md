# 程式碼審查：別人的環形緩衝區有三個 bug

這一節沒有新語法。你要做的是**讀一份別人的實作**，然後修好它。

## 什麼是環形緩衝區

固定容量的「最近 N 筆」容器：滿了就覆寫最舊的。

```
容量 3，push 1,2,3,4：
  初始  [_,_,_]  size 0
  1     [1,_,_]  size 1
  2     [1,2,_]  size 2
  3     [1,2,3]  size 3  ← 滿了
  4     [2,3,4]  size 3  ← 覆寫 1，head 往前推
```

實作只需要一個模運算：第 `i` 個元素（0 = 最舊）在 `data_[(head_ + i) % capacity]`。

## 這份「同事的」程式碼有三個 bug

```cpp
void RingBuffer::push(int value) {
  // 註解說「滿了就覆寫最舊的」，實際上是「滿了就什麼都不做」
  if (size_ < data_.size()) { ... }
  // 少了覆寫最舊元素的分支（也沒有推進 head_）
}
```

| # | 位置 | 錯誤 |
|---|---|---|
| 1 | `push` | 滿了之後直接忽略，沒有覆寫最舊的，也沒有推進 `head_` |
| 2 | `at` | `data_[i]` 少了 `% capacity` 的環繞 |
| 3 | `to_vector` | 由新到舊（方向相反） |

## 為什麼這是「審查」而不是「寫題目」

- 註解**看起來是對的**（它描述的是意圖，不是實作）
- 程式碼**編譯乾淨**（沒有警告）
- 小資料**看起來正常**（未滿時三個 bug 都不會顯現）

真實的審查就是這樣：你必須自己想到「滿了之後呢？」「繞回來呢？」這兩個問題，
然後去看程式碼有沒有回答。

## 三個問題，正好對應三個 bug

1. **滿了之後會怎樣？** → `push` 有沒有 else 分支？
2. **繞回開頭時索引怎麼算？** → 每個讀寫 `data_` 的地方都有 `%` 嗎？
3. **方向對嗎？** → `to_vector` 是從 `head_` 往前還是往後走？

> 審查清單不需要很長。這一節的三個問題就能抓出三個 bug。

## 你要做的事

修好 `submission.cpp` 裡的三個 bug，讓 `RingBuffer` 符合介面語意。

測試會特別檢查這些邊界：容量 1、剛滿、連續覆寫一整圈、push 超過容量 100 次。

# 交付一個完整程式：從 stdin 到排序報表

前面 28 節都是「給你介面、你寫實作」。這一節是相反的：**你交付一個能跑的程式。**

## 規格

```
輸入（stdin）
  第一行：n（品項筆數，可能為 0）
  接下來 n 行：<名稱> <數量> <單價>

輸出（stdout）
  每行：<名稱> <總數量> <總金額>
    以總金額「由大到小」排序；同金額時按名稱字典序（小到大）
  最後一行：TOTAL <總金額>
```

例：

```
輸入                          輸出
3                            banana 1 300
apple 2 100                  apple 2 200
banana 1 300                 cherry 5 100
cherry 5 20                  TOTAL 600
```

看起來簡單。三個地方藏著真實工作的坑。

## 坑一：同名要合併

輸入可能有同一個名稱出現多次（同一天進貨兩次、同一個客戶兩筆訂單）。
報表要的是**每個名稱一行**。這需要「分組聚合」：

```cpp
std::map<std::string, Row> by_name;
Row& r = by_name[name];      // 找不到就建立（operator[] 的語意，這裡正好是我要的）
r.qty    += qty;
r.amount += qty * price;
```

> 注意：`L3.01` 說 `operator[]` 會偷偷插入是陷阱。**同一個特性，在聚合時正好是解法。**
> 工具的特性沒有好壞，只有「在這個情境下對不對」。

## 坑二：tie-break 要寫在比較函式裡

```cpp
std::sort(rows.begin(), rows.end(), [](const Row& a, const Row& b) {
  if (a.amount != b.amount) return a.amount > b.amount;
  return a.name < b.name;          // 同金額：名稱小到大
});
```

兩個細節：

- **不能用 `>=`**。`std::sort` 要求嚴格弱序（`comp(a, a)` 必須是 false），`>=` 會讓相等元素互比都回 true，破壞不變式 —— 實務上會存取越界崩潰。
- **不要排兩次**（先名稱再金額）。第二次排序會覆蓋第一次的結果，除非用 `std::stable_sort`。

## 坑三：金額不是 `int`

`100000 × 100000 = 10¹⁰`，遠超過 `int` 的 2.1×10⁹。有號溢位是 **UB**（見 L4.02），
實務上常見的回繞結果是負數 —— 你的報表就會出現負的總額。

**金額一律用 `long long`**（或更好：用「分」為單位的整數，避免浮點）。

## 為什麼這節用「輸出比對」評測

`io_match` 會把程式的 stdout 與期望**逐字比對**（行尾空白與最後換行會被正規化）。

這比單元測試更接近交付：使用者看到的只有輸出。少一個換行、多一個空格、
數字印成 `1e+10`，都是錯。

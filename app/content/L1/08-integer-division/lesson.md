# 整數除法與轉型

`1 / 2` 在 C++ 裡是 `0`。這不是 bug，是型別決定行為的結果。

## 規則只有一條：結果的型別由運算元決定

```cpp
int    a = 7 / 2;        // 3      整數 / 整數 → 整數
double b = 7 / 2;        // 3.0    ← 先算出 3，才賦值給 b
double c = 7 / 2.0;      // 3.5    有一個運算元是 double → 升級成 double 運算
double d = 7.0 / 2;      // 3.5
```

`double b = 7 / 2;` 是初學者最常誤解的一行：**賦值的型別不會回頭影響右邊怎麼算**。右邊先算完，才輪到左邊。

## 負數：向零截斷，不是向下取整

```cpp
-7 / 2   // -3   （-3.5 → 向零 → -3）
-7 % 2   // -1
 7 / -2  // -3
```

C++ 從 C++11 起明確規定「商向零截斷，且 `(a/b)*b + a%b == a`」。這和 Python 的 `//`（向下取整，`-7 // 2 == -4`）不同，跨語言時要特別注意。

## 什麼時候該明確轉型

只要「小數部分有意義」，就必須讓運算發生在浮點型別上：

```cpp
// 錯：整數除法，結果 0
int p1 = part / whole * 100;

// 對：先轉成 double 再算
int p2 = static_cast<int>(static_cast<double>(part) / whole * 100);
```

`static_cast` 比 C 風格的 `(double)part` 好在**它會明確告訴讀者「這裡有一個刻意為之的轉型」**，而且能被 grep 出來檢查。職場上通常禁止 C 風格轉型。

## 四捨五入不是「整數除法 + 1」

要 `1/3 → 33%`、`2/3 → 67%`，得做真正的四捨五入：

```cpp
#include <cmath>
std::lround(part * 100.0 / whole)   // 回傳 long
```

如果只想用整數，正數的情況可以寫 `(part * 100 + whole / 2) / whole`。但這個式子對負數會錯 —— 這也是為什麼多數人直接用 `std::lround`。

> 一個職場等級的習慣：**不要在心裡算，讓型別幫你算**。
> 看到 `/` 就先問「兩邊是什麼型別？」，看到 `int` 接浮點結果就問「這裡是不是該有 explicit cast？」。

## 你要實作的三個函式

```cpp
// 1) a 與 b 的整數平均（向零截斷）
int int_average(int a, int b);

// 2) a 與 b 的浮點平均
double real_average(int a, int b);

// 3) part 佔 whole 的百分比，四捨五入到整數；whole == 0 時回傳 0
int percent(int part, int whole);
```

起始碼三個都寫好了，但都有微妙的錯誤。測試會精準地指出是哪一個—— 特別是 `int_average(1, 1)` 這個看起來毫無意義的案例。

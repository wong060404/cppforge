# 從 stdin 讀資料

前兩節的程式不讀輸入。真實的程式幾乎都要：讀設定、讀請求、讀使用者打的字。

## `std::cin >>` 到底做了什麼

```cpp
int n = 0;
std::cin >> n;
```

這行的意思是「**跳過前導空白，然後盡可能解析出一個 int**」。細節決定了很多行為：

- 它自動跳過空白（空白、Tab、換行都算），所以你可以用空白或換行分隔資料，效果一樣。
- 它回傳 `std::cin` 本身，所以可以串接：`std::cin >> a >> b;`。
- **解析失敗時它不改動你的變數**，只把 stream 標記成失敗狀態。

最後一點是最容易踩的坑：

```cpp
int n = 42;
std::cin >> n;      // 輸入是 "abc"
// n 仍然是 42；cin 進入 fail 狀態
```

更麻煩的是，一旦進入 fail 狀態，**之後每一次 `>>` 都直接失敗**，不會有任何提示。程式看起來「跑完了」，但讀到的全是預設值。

> 職場對策：讀完之後檢查 `if (!std::cin) { /* 處理錯誤 */ }`。讀一整行則用 `std::getline`。
> 注意 `>>` 與 `getline` 混用時，`>>` 會把換行留在緩衝區，`getline` 立刻讀到空行 —— 這是另一個經典坑。

## 三個狀態的迴圈

題目要同時輸出總和、筆數、最大值。這是「多個累加器」的典型寫法：

```cpp
int sum = 0;
int count = 0;
int max = <種子>;
for (int i = 0; i < n; ++i) {
  int x = 0;
  std::cin >> x;
  sum += x;
  ++count;
  if (x > max) max = x;
}
```

**種子怎麼選？** 這題的陷阱就在這裡。

如果寫 `int max = 0;`，那麼當所有輸入都是負數時（例如 `-9 -1 -5`），`x > 0` 永遠不成立，`max` 會停在 0 —— 答案是錯的，但程式不會崩潰、編譯器不會警告。

兩種正確做法：

1. `int max = values[0];`（用第一筆當種子，之後從第二筆開始比）
2. `int max = std::numeric_limits<int>::min();`（用型別能表示的最小值）

## 題目規格

輸入格式：

```
N
a1 a2 ... aN
```

`N` 是本筆測試的數字個數（`N >= 1`），接著是 `N` 個整數（可能跨多行）。

輸出格式（**逐字相符**，單行，結尾換行）：

```
sum=<總和> count=<個數> max=<最大值>
```

例如輸入 `5` 與 `3 1 7 2 2`，輸出：

```
sum=15 count=5 max=7
```

> 為什麼要逐字相符？因為自動評測比對的是位元組。`sum=15` 與 `sum = 15` 是兩份不同的輸出。職場的 API 契約、報表格式也是這樣 —— 差一個空格就是 bug。

## 你要做的事

改寫 `submission.cpp` 的 `main`，完成三件事：

1. 讀一個 integer `n`（element 個數，`n >= 1`）
2. 再讀 `n` 個 integer（可能有負數，用空白或換行隔開）
3. 輸出**一行**：`sum=<總和> count=<n> max=<最大值>`，結尾要有換行

範圍提醒：`n` 可到 1000，總和可能超過 `int` 之外嗎？本節不需要擔心（測資在範圍內），
但 `max` 的初始值要想清楚—— 用 `0` 起頭的話，全部是負數的測資就會錯。

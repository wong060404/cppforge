# 編譯不是一個動作

你在編輯器按下「建置」時，其實發生了三到四件不同的事。搞不清這幾件事，就會在錯誤訊息前面卡很久 —— 因為**不同階段吐出的錯誤，修法完全不同**。

## 從 .cpp 到 .exe 的四個階段

```
你的 .cpp
   │  ① 前置處理（preprocess）  #include、#define、#if 的文字替換
   ▼
展開後的「翻譯單元」
   │  ② 編譯（compile）        語法檢查、型別檢查 → 產生組合語言
   ▼
組合語言
   │  ③ 組譯（assemble）       轉成機器碼 → .o / .obj
   ▼
目的檔
   │  ④ 連結（link）           把多個 .o 與函式庫串起來 → .exe
   ▼
執行檔
```

在多數工具鏈裡，你打一行 `g++ main.cpp -o main.exe`，這四步會一次跑完。但**錯誤是分階段發生的**，這是重點。

## 三種錯誤，三種長相

| 階段 | 訊息長相 | 典型原因 | 你的動作 |
|---|---|---|---|
| 前置處理 | `fatal error: iostream: No such file or directory` | 拼錯標頭名稱、路徑不對 | 檢查 `#include` |
| 編譯 | `error: 'y' was not declared in this scope`、`expected ';'` | 語法、型別、名稱錯誤 | 修程式碼 |
| 連結 | `undefined reference to 'helper()'` | 有宣告、沒定義；漏了 .cpp | 補定義或補檔案 |

看到 `undefined reference` 時，直覺反應常是「我是不是漏了 `#include`？」——**不是**。那是連結階段，代表編譯已經成功，缺的是實作。

## main 為什麼回傳 int

```cpp
int main() {
  // ...
  return 0;
}
```

`return 0;` 其實可以省略（標準規定走到 `main` 結尾等於 `return 0;`），但**回傳型別必須是 `int`**。

`void main()` 在某些舊的編譯器上「能過」，那不是合法 C++，只是那個編譯器懶得檢查。換到 Linux 上的 g++ 就會直接拒絕。**能編譯 ≠ 合法** —— 這是本課程會反覆出現的一句話。

## 實作：讓輸出逐字相符

現在換你操作。下面是起始碼，它會印出一段文字，但**不是**題目要求的內容。

要求：讓程式輸出（結尾包含換行）：


注意：自動評測會逐字比對（只忽略行尾空白與檔尾換行）。少一個逗號、多一個空格都算錯—— 這正是職場的規格比對。

## 一個常見陷阱

```cpp
#include <iostream>
int main() {
  std::cout << "hello" << std::endl;   // 有換行
  std::cout << "hello";                // 沒有換行
}
```

`std::endl` 會插入 `'\n'` 並強制 flush；`"\n"` 只插入換行。兩者的輸出位元組相同（差在 flush 時機）。輸出比對看的是**位元組**，不是你看起來的樣子。

> 小結：編譯器不會告訴你「你的輸出格式不對」——那要靠測試。這也是為什麼每一節都有自動評測。

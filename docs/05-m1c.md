# M1 · 第三切片：內容廣度（L1.08–L1.11）

> 版本 v0.1 · 接續 `04-m1b.md`
> 目標：複習系統需要足夠的卡片才有意義。先補 L1 的廣度。

---

## 1. 為什麼先補內容

上一輪做完複習系統時，全站只有 **12 張概念卡**。這有兩個問題：

1. **看不出排程效果**：卡片太少，間隔拉開後就沒東西可複習。
2. **課程有明顯缺口**：`for`/`while`、固定陣列、`struct`、`enum` 這些每天都會用到的東西，
   在原來的 10 節裡完全沒有。

所以這一輪加了 4 節（10 → 14 節），卡片 12 → 20 張。

---

## 2. 新增的四節

| 節點 | 主題 | 三個要修錯的函式 | 教學重點 |
|---|---|---|---|
| **L1.08** | 迴圈：for / while / do-while 各管什麼 | `factorial`、`is_prime`、`first_non_space` | 累乘的單位元素是 1（用 0 啟動永遠得 0）；2 是唯一偶數質數；「找空白」與「找非空白」的差別 |
| **L1.09** | 固定大小陣列：`std::array` | `sum_array`、`reverse_array`、`index_of_max` | 越界會被除錯模式抓到；「走訪全部做對稱交換」等於換兩次＝沒換；回傳索引不是值 |
| **L1.10** | struct：把資料綁在一起 | `manhattan`、`rect_area`、`rect_contains` | 四個同型別參數是 bug 溫床；退化矩形（反向左上右下）必須定義行為；`<=` 與 `<` 的差異就是「含不含邊界」 |
| **L1.11** | enum class 與 switch | `turn_right`、`to_chinese`、`delta` | `West+1` 會造出不合法列舉值；`default:` 會讓 `-Wswitch` 失效；窮舉式 switch 是最好的自我檢查 |

四節串成線性先修鏈：`L1.07 → L1.08 → L1.09 → L1.10 → L1.11`。

### 為什麼每個節點都是「三個近似正確但各錯一處」

這是刻意的格式。好處：

- 學員不會被「整段重寫」嚇到，改動幅度小、心理門檻低。
- 三個錯誤**型態不同**（初始化、邊界、語意），強迫逐個診斷而不是套同一個模板。
- 測試會精準指出哪一個錯 —— 這比「全部重來」更接近真實的維護工作。

## 3. 驗證證據

| 驗證 | 方法 | 結果 |
|---|---|---|
| 內容 CI | 14 節 × 2 變體（參考解必過 / 起始碼必敗） | **14/14 全過** |
| 學習鏈 | 空資料庫，逐節送參考解、每輪重取狀態 | **14/14 通過**，先修鏈正確 |
| 卡片解鎖 | 每通過一節就查一次卡片總數 | **3 → 20**，只在解鎖時才補卡 ✅ |
| UI | `dom-smoke --run` | **28/28** |
| 圖鑑 | `atlas.test.mjs` | 19/19 真實訊息 |
| 排程 | `srs.test.mjs` | 全過 |

卡片成長軌跡（實際記錄）：

```
L0.01 →  3 張    L1.02 →  9 張    L1.06 → 12 張    L1.09 → 18 張
L0.03 →  3 張    L1.04 → 12 張    L1.07 → 14 張    L1.11 → 20 張
L1.01 →  6 張    L1.05 → 12 張    L1.08 → 16 張
```

（L0.02/L0.03 沒有概念卡，所以通過後數字不變；L1.01 通過時解鎖 L1.02，+3。）

## 4. 這一輪修掉的問題

| 問題 | 影響 | 修法 |
|---|---|---|
| `newCards` 虛報 | 重複犯同一個錯時，UI 仍說「已加入複習（1 張錯誤卡）」 | `addErrorCards` 先查 `cardBySource`，只計真正新建的卡 |
| 卡片在冷啟動就全部到期 | 一開機有 12 張待複習（含沒讀過的課），只會逼人按「忘記了」 | 只為**已解鎖**的節點建卡；通過後才補 |

兩者都屬於「功能會動，但會對使用者說謊」的類型 —— 這也是為什麼要有 smoke test
和手動的端到端檢查，不能只看單元測試綠燈。

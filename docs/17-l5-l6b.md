## 1. L5.03 記憶體與容器選擇

這一節第一次用**靜態規則**約束「怎麼寫」，而不只是「結果對不對」：

| 規則 | 類型 | 為什麼 |
|---|---|---|
| `.reserve(` | **必須** | 已知大小的結果不該讓 `push_back` 反覆重新配置 |
| `std::list` | 禁止 | 節點各自配置、cache 不友好，幾乎總比 vector 慢 |
| `new` / `delete` | 禁止 | 手動管理記憶體是唯一能「沒寫錯任何一行卻洩漏」的東西 |

起始碼實測：

```
static_rules  fail  發現 1 處違規
  · [use-reserve] 已知大小的結果必須先 reserve
unit_test     fail  4 過 / 6 敗
```

**為什麼需要靜態規則？** 因為「沒有 reserve」不影響正確性 —— 測試永遠是綠的。
這是效能與正確性的分工：測試管行為，靜態規則管紀律。

## 2. L6.03 程式碼審查

給一份**別人的**環形緩衝區實作，附上看起來很有說服力的註解：

```cpp
void push(int value) {
  // 註解說「滿了就覆寫最舊的」，實際上是「滿了就什麼都不做」
  if (size_ < data_.size()) { ... }
  // 少了覆寫最舊元素的分支
}
```

三個 bug：

| # | 位置 | 錯誤 |
|---|---|---|
| 1 | `push` | 滿了直接忽略，沒有覆寫最舊、沒有推進 `head_` |
| 2 | `at` | `data_[i]` 少了 `% capacity` 的環繞 |
| 3 | `to_vector` | 由新到舊（方向相反） |

**共同點：未滿時三個 bug 都不會顯現。** 這就是審查的價值 ——
你必須自己問「滿了之後呢？」「繞回來呢？」。

測試刻意涵蓋：容量 1、剛滿、連續覆寫一整圈、push 105 次。

## 4. 七個等級（每級 ≥ 3 節）

| 等級 | 節點 | 評測機制 |
|---|---|---|
| L0 環境與心智模型 | 3 | 編譯、輸出比對、連結 |
| L1 語言基礎 | 11 | 編譯 + 隱藏測試 + 邊界檢查 |
| L2 物件與資源 | 6 | 測試 + **洩漏/double free** |
| L3 泛型與標準庫 | 4 | 測試 + **容器比對印元素** |
| L4 工程化與正確性 | 3 | 測試 + **`-fanalyzer`** |
| L5 效能與併發 | 3 | 測試 + **複雜度預算** + **必須寫法** |
| L6 職場整合 | 3 | 測試 + **輸出逐字比對** |

**六種 grader 全部都有節點在用**：`compile`、`unit_test`、`io_match`、
`runtime_safety`、`static_rules`、`analyzer`。

## 1. 為了 L3.04，先加了一個引擎能力

模板的定義**必須在標頭檔**（編譯器要在具現化點看到定義）。但我們的評測模型原本固定
把提交寫成 `submission.cpp` 當獨立 TU 編譯 —— 模板放進去會連結失敗。

所以加了 `submissionName` 欄位（預設 `starter.cpp`）：

| 情況 | 行為 |
|---|---|
| 一般節點 | 提交寫成 `submission.cpp`，與 `tests.cpp` 一起編譯 |
| 標頭節點（`submissionName: "submission.hpp"`） | 提交放進 include 目錄、**不**當獨立 TU；編譯檢查改用一個只 `#include` 它的探針 |

配套改動：

- `content.mjs` lint：一般節點檢查 `starter.cpp` + `.meta/solution.cpp`；標頭節點兩邊同名
- 標頭提交**不能**宣告 `io_match`（不可能有 `main`），lint 會直接擋
- UI 的檔名顯示改讀 `submissionName`（會顯示 `submission.hpp`）

> 這個能力本身是教材：學員看到「檔案是 .hpp」就會問為什麼，而課文第一段就在回答。

## 2. L3.04 泛型入門

| 項目 | 內容 |
|---|---|
| 介面 | `concept Addable`（`a + b` 且可轉回 `T`）＋ 三個樣板宣告 |
| 要實作 | `sum_all<T>`、`greater_than<T>`、`min_max<T>`（都在 `.hpp`） |
| 要修的錯 | 迴圈從索引 1 開始（漏第一個）、`>=` 而非 `>`、`{max, min}` 順序反了 |

**測試刻意跨型別**：`sum_all({1,2,3}) == 6`、`sum_all({"ab","cd","e"}) == "abcde"`、
`sum_all({1.5, 2.5}) == 4.0`。同一份程式碼要同時通過 —— 這才是「泛型」的證明。

三個錯的共同點：**它們跟型別無關**。樣板讓你把邏輯寫一次，所以一個邏輯錯會同時影響所有型別。

## 3. L4.01 例外安全（L4 開場）

| 項目 | 內容 |
|---|---|
| 型別 | `ScopeGuard`（解構時執行清理動作的 RAII 工具） |
| 要實作 | ctor / dtor / `release()` / `active()` / 移動 ctor / 移動賦值 / `make_guard` |
| 要修的錯 | dtor 沒檢查「是否已取消」、移動 ctor 沒清來源、移動賦值沒清來源 |

### 這一節抓到的兩個設計問題

**（1）測試期望值寫錯。** 我原本假設「移動賦值會執行目標舊的動作，再接手新的」——
實際上 move 賦值是**丟棄**舊動作。測試紅了，我才發現自己在教一個錯誤的語意。

**（2）三個錯被兩個測試遮住。** 第一版把 `release()` 也寫成錯的，結果
「解構函式沒看旗標」這個錯**觀察不到**（因為根本取消不了）—— 訊號只有 2，低於宣稱的 3。

改法：`release()` 保持正確，讓「解構不看旗標」獨立可觀測；三個錯分別由三個測試抓到：

| 漏掉的地方 | 由哪個測試抓到 |
|---|---|
| 解構時不看旗標 | `release() 之後不再執行` |
| 移動 ctor 不清來源 | `移動之後只執行一次` |
| 移動賦值不清來源 | `移動賦值：接手後只執行一次` |

修正後訊號 = **3**，與宣稱完全一致 —— 這是目前 25 節裡最乾淨的一次。

## 1. 補上 4 節基礎語法（L1.01–L1.04）

原本 L1 直接從「從 stdin 讀資料」開始 —— 等於假設你已經會變數、if、函式。
這是個大洞，現在補上：

| 節點 | 主題 | 教什麼 | 三個要修的錯 |
|---|---|---|---|
| **L1.01** | 變數、型別與初始化 | int/double/bool/string、宣告 vs 初始化、整數除法、bool 隱式轉換 | 整數除法截斷、`return x % 2` 回傳餘數、`x >= 0` 把 0 判成正數 |
| **L1.02** | 運算子與優先序 | 優先序表、**連鎖比較陷阱**、複合賦值、`i++`/`++i`、短路求值 | 累乘起始值 0、三段式 max3 漏值、`lo < x < hi` |
| **L1.03** | 條件分支 | if/else if/else、`<` vs `<=` 的邊界、條件由嚴到寬、guard clause | 90 分掉到 B、`clamp` 沒處理 `lo > hi`、閏年漏世紀規則 |
| **L1.04** | 函式 | 宣告/定義/呼叫、傳值 vs 傳參考、參考參數、range-for 的 `&`、區域變數壽命 | 寫進區域變數、沒用 `times`、改到副本 |

**原有的 11 節順移為 L1.05–L1.15**（連目錄名一起改），先修鏈重接：

```
L0.03 → L1.01 型別 → L1.02 運算子 → L1.03 分支 → L1.04 函式
      → L1.05 I/O → … → L1.15 enum → L2.01
```

每一節只用到前面教過的東西。例如 L1.02 的迴圈只在「次方」那題出現，
而且課文先把 `for` 講清楚才用。

### 過程中 `-Werror` 幫了大忙

第一版的起始碼有 4 個地方**編不過**：

| 節點 | 錯誤 | 原因 |
|---|---|---|
| L1.02 | `unused parameter 'c'` | 「只比兩個」的寫法根本沒用到 c |
| L1.02 | `comparisons like 'X<=Y<=Z' do not have their mathematical meaning` | 我故意寫的連鎖比較被 GCC 直接抓出來 |
| L1.04 | `unused parameter 'quotient'` ×2 | 「寫進區域變數」的寫法讓兩個參考參數沒被用到 |
| L1.04 | `variable 'x' set but not used` | range-for 改副本 |

依規則「起始碼必須能編譯」，我把錯誤改成**能編譯但邏輯錯**的版本：
`max3` 改成三段式（會漏值）、`in_range` 改成嚴格比較（排除邊界）、
`divmod` 改成商餘寫反、`scale_in_place` 改成「算出來但沒寫回」。

> 順帶記一筆：GCC 的 `-Wparentheses` 對 `a < b < c` 有專門的警告訊息，
> 這比「執行後發現結果怪」早了幾步。

## 2. 每關的指引：新增「怎麼做」步驟

「本節任務」卡現在有三層：

```
┌ 本節任務 ────────────────────────────────┐
│ ▸ tasks.hpp（唯讀，展開就是規格）          │
│                                           │
│ 怎麼做                                     │
│  1. 先讀下面的介面檔：型別、參數、回傳值…   │
│  2. 改右側程式碼，先讓「編譯」變成 PASS     │
│  3. 看失敗的測試名稱 —— 那就是規格          │
│  4. 測試全過後再看「記憶體安全」            │
│                                           │
│ [看提示（0/3）]                            │
└───────────────────────────────────────────┘
```

**步驟會依這一節實際跑的 grader 自動產生**，所以每一節的步驟都不一樣：

| grader | 產生的步驟 |
|---|---|
| `compile` | 先讓「編譯」這一列變成 PASS（訊息的行號就是位置） |
| `unit_test` | 看失敗的測試名稱 —— 那就是規格，一次修一個 |
| `io_match` | 用題目給的測資自己比對輸出：空白、換行、大小寫都算 |
| `runtime_safety` | 測試全過之後再看「記憶體安全」 |
| `static_rules` | 注意有些寫法被禁止、也有些是**必須**使用的 |
| `analyzer` | 看靜態分析指出的行號 |

四節新節點另外手寫了更具體的步驟（指向實際的三個 bug）。

## 3. 每關的提示：一次揭露一條

**37 節、共 84 條提示**（每節 2–3 條）。設計原則：

- **第一條**指向「去哪裡看」（測試名稱／介面／訊息行號）
- **第二條**直接講那個誤解（不是「再想想」，是「`x % 2` 是 int 不是 bool」）

實際例子：

| 節點 | 提示 |
|---|---|
| L1.01 | 整數除整數永遠是整數：`(1+2+2)/3` 是 1，不是 1.666… |
| L1.02 | `lo < x < hi` 會先算 `lo < x` 得到 bool，再拿 bool 跟 hi 比 |
| L2.04 | 深拷貝要 `new int[n]` **再加上** `std::copy`；只配置不複製，內容會全是 0 |
| L5.02 | 分段時 `n % k` 的餘數要分給前幾個執行緒；`k > n` 要把執行緒數夾到 n |

點一次顯示一條，按鈕上顯示 `看提示（1/3）`，全部顯示後按鈕停用 ——
先自己想，想不出來再看下一條。

## 4. 四條新的內容 lint 規則

```
XX: 提示少於 2 條（hints）—— 卡住的人沒有後路
XX: hints[0] 太短（少於 12 字），寫具體一點
XX: steps 只有 1 步，要嘛寫完整、要嘛留空讓系統自動產生
XX: 課文缺少任務段落（建議「## 你要實作的部分」）
```

未來新增節點若忘記寫提示，內容 CI 直接失敗。

## 5. 檢查軟體時抓到的 5 個 bug

| # | 問題 | 影響 | 修法 |
|---|---|---|---|
| 1 | API 沒有回傳 `steps` / `hints` | 前端拿不到，任務卡永遠只有介面檔 | `loadNode` 補上兩個欄位 |
| 2 | `app.js` 讀 `node.graders`，但 API 放在 `graderSummary.graders` | 自動步驟退化成一句話（只有 1 步） | 改讀 `node.graderSummary.graders` |
| 3 | DOM shim 的 `getElementById` 另造物件，不是 innerHTML 解析出來的節點 | 「點提示後 append 的內容」在教學區看不到（測試也抓不到） | 改成註冊解析出來的節點 |
| 4 | shim 的 `textContent` setter 沒清子節點 | 按鈕文字更新後讀到的還是舊值 | 依真實 DOM 行為清掉子節點 |
| 5 | 我自己寫的選項含反引號 | 選項不渲染 Markdown，會顯示成原始符號 | 內容 lint 已擋（本輪自己踩到一次） |

第 3 點特別值得記：shim 和瀏覽器的行為不一致時，**測試會替 bug 掩護**。

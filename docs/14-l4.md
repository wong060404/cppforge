## 1. 一個「文件宣稱但程式裡不存在」的功能

README 從 M0 起就寫「6 種 grader：編譯、隱藏測試、輸出比對、記憶體安全、靜態規則、**`-fanalyzer`**」。
但 `grading.mjs` 的 `GRADERS` 只有 **5** 個 —— `analyzer` 從來沒被實作。

L4.02 的主題剛好就是靜態分析，所以這輪把它補上：

```js
async function gradeAnalyzer(ctx) {
  // -fanalyzer 只產生 warning，編譯仍然成功，所以必須獨立成一個 grader
  g++ -fanalyzer -Wall -Wextra -c submission.cpp
}
```

只採計「提交檔（或標頭提交的探針）」裡的診斷，系統標頭的警告不算學員的。

### 實測：`-fanalyzer` 到底抓得到什麼

我先寫了一個探針檔，把六種常見缺陷放進去實跑：

| 模式 | `-fanalyzer` 的反應 |
|---|---|
| 記憶體洩漏 | ✅ `leak of 'p' [CWE-401]` |
| 空指標解參考 | ✅ `dereference of NULL 'p' [CWE-476]` |
| 使用未初始化的值 | ✅ `use of uninitialized value [CWE-457]` |
| 陣列越界讀 | ✅ `stack-based buffer over-read [CWE-126]` |
| **有號整數溢位** | ❌ 完全沒有警告 |
| 除以零（常數） | ❌ 沒有警告 |

這張表變成 L4.02 課文的一部分 —— **工具的能力有邊界**，這比「用它就好」誠實得多。

### 隨之調整的題目設計

原本 `midpoint` 的溢位是主角，但分析器看不到它。所以我加了第四個函式 `first_of`：

```cpp
int first_of(std::size_t n) {
  int* p = new int[n];   // 沒有 delete[]
  p[0] = 42;
  return p[0];
}
```

它的**測試完全正常**（回傳 42），只有分析器與洩漏檢查抓得到。
於是這一節的五種問題由**三種不同機制**抓到：

| 函式 | 問題 | 誰抓到 |
|---|---|---|
| `midpoint` | 有號溢位（UB） | 只有**測試** |
| `first_of` | 洩漏 | **分析器** + 洩漏檢查 |
| `clamp_byte` | 沒夾範圍 | 測試 |
| `safe_at` | 越界拋例外（違反契約） | 測試 |

實測輸出：

```
起始碼  unit_test  fail  6 過 / 6 敗
        analyzer   fail  分析器發現 1 個問題：leak of 'p' [CWE-401]
參考解  unit_test  pass  12/12
        analyzer   pass  分析器沒有發現問題
```

## 2. L4.03 錯誤處理策略

三個函式、同一件事、三種契約：

| 函式 | 契約 | 起始碼的錯 |
|---|---|---|
| `to_int_opt` | 失敗回 `nullopt`，**絕不拋** | 直接回 `std::stoi` → 會拋、又接受 `"12x"` |
| `to_int_or_throw` | 失敗丟 `invalid_argument` | 把例外吞掉回 0 → **永不失敗** |
| `to_int_outcome` | 失敗 `ok == false`，**絕不拋** | 永遠 `ok = true` |

這節的核心不是「選一個最好的」，而是**契約是合約**：

> 介面寫「絕不拋例外」，就是承諾所有輸入都不拋。呼叫端看到 `optional` 就假設不會拋，
> 所以沒寫 try/catch —— 一旦真的拋，例外一路穿出去就是 `std::terminate`。

測試也刻意分成三組（各 4–6 個），讓每個函式的契約 violation 各自可見。

# M1 · 第一切片：錯誤圖鑑 + UI 冒煙測試

> 版本 v0.1 · 接續 `02-m0.md`
> M0 已經能「讀課 → 寫碼 → 跑評測 → 存進度」。M1 的第一件事不是加更多課，
> 而是把「錯誤是一等公民」這條原則做成真的功能。

---

## 1. 為什麼先做錯誤圖鑑

M0 結束時，學員看到錯誤只會拿到 1–2 句提示（`grading.mjs` 裡的 10 條 `HINTS`）。
問題有三個：

1. **提示是字串**，無法展開、無法查、無法從錯誤跳到解釋。
2. **覆蓋率太低**：10 條提示 vs 幾十種常見錯誤。
3. **沒有「為什麼」**：只說「怎麼修」，學員下次還是會犯。

所以把它升級成一個資料驅動的知識庫：每條都有 **症狀 → 為什麼 → 怎麼修 → 錯誤/正確對照**，
並且用「編譯器真的會印出來的字串」與實際錯誤掛鉤。

## 2. 結構

```
app/server/data/atlas.mjs    21 條資料（純資料，無邏輯）
app/server/atlas.mjs         比對引擎：listAtlas / getEntry / matchAtlas
```

條目格式：

```js
{
  id: "undefined-reference",
  stage: "連結",
  match: ["undefined reference to"],       // 真的會出現在輸出裡的字串
  title: "連結錯誤：找不到定義",
  symptom: "undefined reference to `square_area(int)'",
  why: "編譯器看到宣告就放行了，連結器才是真正配對的階段。",
  fixes: ["忘了把 .cpp 加進編譯指令", "簽章不一致", …],
  bad: "// tasks.hpp 宣告了，但沒有任何定義",
  good: "// submission.cpp\nint square_area(int side) { return side * side; }",
}
```

### 涵蓋範圍（21 條）

| 階段 | 條目 |
|---|---|
| 前置處理 | 標頭檔找不到 |
| 編譯（語法） | 少分號、括號沒收尾、全角引號、縮窄轉換 |
| 編譯（名稱/型別） | 名稱不在作用域、沒有可用多載、型別轉換失敗、const 丟失、非 const 參考绑臨時值、有號無號比較 |
| 連結 | undefined reference、重複定義、找不到進入點 |
| 執行期 | segfault、越界、記憶體洩漏、堆疊溢位、逾時、除以零、測試沒跑起來 |

### 比對規則（刻意保守）

- **子字串比對、大小寫不敏感**，不做模糊推測 —— 寧可漏，不要給錯答案。
- 一條輸出可命中多條（越界同時命中 segfault 與 out-of-bounds），**按階段排序**。
- **通過的提交不給圖鑑**：正常輸出難免含有關鍵字（例如 `TESTS:`），顯示只會造成噪音。
- `match` 少於 3 個字元會被內容 CI 擋下（避免 `逾時` 這種過度匹配）。

## 4. 驗證證據

| 驗證 | 方法 | 結果 |
|---|---|---|
| 比對引擎命中率 | 8 組真實訊息 → 期望條目 | **8/8** |
| 誤匹配 | 正常測試輸出（`TESTS: 7 passed`） | 修正後 **0 命中** |
| 資料完整性 | 內容 CI 新增 `lintAtlas()`（id 唯一、必要欄位、match 長度） | **21 條 0 問題** |
| API | `GET /api/atlas`、`/api/atlas/:id` | 200，21 條 |
| 端到端 | 送出「故意編不過」的程式 → chips 出現 → 點擊開啟 | 通過 |
| UI 冒煙 | `node app/test/dom-smoke.mjs --run` | **19/19** |

### 內容 CI 抓到的兩個真問題

1. `timeout` 條目的 match 寫成 `"逾時"`（2 個字）→ 任何含「逾時」的文字都會命中。已改為 `逾時（`、`（逾時）` 等。
2. `test-not-run` 的 match 含 `"TESTS:"` → 正常的測試輸出也會命中。已移除。

這兩個都是「寫的時候看起來沒問題」的錯，靠規則擋下來。

## 5. UI 冒煙測試（新工具）

**背景**：本機無法啟動無頭瀏覽器 —— Chromium 需要具名管道，而執行環境封鎖了它
（`FATAL: mojo platform_channel: Check failed: Access is denied`）。所以改用
Node + 最小 DOM shim **真的執行 `app.js`**。

它不是視覺測試，但能抓到真正的執行期錯誤：

| 抓到的問題 | 類型 |
|---|---|
| `window.addEventListener is not a function` | 真 bug（shim 缺方法，但證明程式碼會炸） |
| fire-and-forget 的非同步例外 | 會被轉成 `unhandledRejection`，現在收集後判失敗 |
| 事件處理器重複註冊造成無限迴圈 | shim 行為不符瀏覽器（已修正 shim，非 App 問題） |
| `deepHtml()` 沒序列化 className | 測試斷言寫錯（已修） |

**已知限制（誠實記錄）**：不能驗證版面、CSS、Monaco 的實際渲染。
那些仍然需要人眼確認 —— 這也是為什麼 `docs/02-m0.md` §7 把它列為待辦。

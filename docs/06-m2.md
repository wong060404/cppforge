# L2 開場：物件與資源（L2.01–L2.03）

> 版本 v0.1 · 接續 `05-m1c.md`
> 目標：跨過「語法」到「物件」這條線。這是 C++ 與其他語言最大的分歧點。

---

## 1. 為什麼 L2 是分水嶺

L0/L1 的 14 節都在回答「這個語法怎麼寫」。L2 開始要回答另一個問題：

> **物件活著的時候，它保證什麼？死了之後，誰負責？**

這就是 RAII。沒有它，C++ 只是一門語法複雜的語言；有它，你才能寫出「即使拋例外也不會漏資源」的程式碼 —— 而這是職場 C++ 的門檻。

三節刻意排成**手寫 → 出錯 → 換工具**的順序：

```
L2.01  class 與不變式      → 物件要有「規則」
L2.02  手寫 new/delete     → 規則守不住（洩漏），而且你得記三件事
L2.03  unique_ptr          → 換掉成員，三件事變成零件事
```

L2.02 的錯誤在 L2.03 會被**解決**，而不是被「再提醒一次」。這是刻意設計的教學曲線。

---

## 2. 三節的內容

| 節點 | 主題 | 三個要修的錯 | 教學核心 |
|---|---|---|---|
| **L2.01** | class 與不變式 | 建構子沒驗證、`increment()` 沒夾住、`add()` 沒拒絕負數 | 不變式 `0 <= value_ <= max_`；「滿了」是合法狀態、「負增量」是錯誤 → 兩者處理方式不同 |
| **L2.02** | 建構子／解構函式 | 解構函式空的（洩漏）、`set()` 沒邊界檢查、`at()` 沒邊界檢查 | 生命週期四時機（正常返回／例外／提早 return／scope 結束）；`delete[]` 與 `delete` 的差別 |
| **L2.03** | RAII 與 unique_ptr | `size()` 多算一、`empty()` 判斷相反、移動建構子沒把來源歸零 | rule of zero；移動是「交出去並清空」；`noexcept` 為何影響 `std::vector` 的行為 |

先修鏈：`L1.11 → L2.01 → L2.02 → L2.03`。

### 兩個教材設計細節

1. **L2.02 的洩漏是「真的會被工具抓到」**。評測會用 `operator new` 攔截跑一次測試（Windows 沒有 ASan，這是替代方案），
   所以「忘記 delete」不再是「看起來沒事」—— 它會讓 `runtime_safety` 直接 FAIL。
2. **L2.03 的 `empty()` 與移動建構子是同一件事的兩面**：物件「回報的狀態」必須和「實際狀態」一致。
   測試裡有一項 `移動後來源可以被重新使用`，確保來源不是「半死」而是明確的空。

### 這輪新增的一個檢查

內容 CI 之前只驗「參考解會過、起始碼會敗」。但課文宣稱**「三個函式各有一個錯」**——
如果實際只有一個錯造成連鎖失敗，這個宣稱就是假的，學員會以為自己漏看了兩個。

所以加了：起始碼造成的失敗測試數必須 ≥ `bugCount`（節點宣告）。
一個 bug 通常會讓多個測試失敗，所以用「≥」而非「=」。這條規則抓不到
「一個 bug 剛好讓 3 個測試失敗」的誤報，但至少能擋住「宣稱 3 個、實際 1 個」。

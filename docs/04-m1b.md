# M1 · 第二切片：間隔複習（FSRS 形式）

> 版本 v0.1 · 接續 `03-m1.md`
> 目標：把「學過就忘」接住 —— 這是一個訓練系統與一本教程最大的差別。

---

## 1. 為什麼要做，以及為什麼不是「再加幾節課」

M0 的十節課可以讓人「當場會」。但三天後回頭看 `size_t` 的題，多數人會卡住 ——
這不是理解力問題，是**遺忘曲線**：沒有複習的知識會以指數速率衰減。

一般平台的解法是「再加練習題」。問題是：你已經做對的題，再出現一次你不會認真看；
真正需要的是**在你快忘記的那一刻**，用最短的形式（一張卡）把你拉回來。

## 2. 演算法：FSRS 形式，但誠實標示限制

`app/server/srs.mjs` 實作的是 FSRS 的**模型形式**：

| 元件 | 內容 |
|---|---|
| 遺忘曲線 | `R(t) = (1 + 19/81 · t/S)^(-0.5)`；`t = S` 時 `R = 0.9` |
| 兩個狀態 | `S`（穩定度，天）與 `D`（難度，1–10） |
| 四個評分 | 忘記了 / 很吃力 / 想起來了 / 太簡單 |
| 難度回歸 | 每次評分後往初始難度做 10% 均值回歸（避免「難度地獄」） |

**⚠️ 限制（必須說清楚）**：
- 權重是**手動設定的**，不是 FSRS-4.5 的官方參數，也沒有用真實資料校準。
- 所以產出的間隔**不會**與 Anki 一致。目的不是複製 Anki，而是讓遺忘被系統接住。
- 未來有足夠複習記錄後，可以換成校準過的權重（介面已隔離在 `WEIGHTS`）。

### 關鍵設計：用「目標記住機率」推導間隔

第一版把間隔算成「穩定度 × 一個倍數」，結果四個按鈕的間隔只差幾個百分點
（實測：很吃力 1.4 個月 / 想起來了 1.4 個月）—— 學員根本感受不到差別，按鈕等於失效。

改成：**每個評分對應一個目標記住機率**，再用遺忘曲線反推天數。

| 評分 | 目標記住機率 | 意義 |
|---|---|---|
| 忘記了 | 0.97 | 幾乎明天就要再看到 |
| 很吃力 | 0.95 | 短間隔 |
| 想起來了 | 0.90 | 標準 |
| 太簡單 | 0.85 | 可以隔久一點 |

這樣「忘記了 vs 太簡單」天然差 6 倍，而且**可以對學員解釋**：
「你要多高的把握？」比「ease factor 乘 1.3」有意義得多。

實測數字（新卡）：`2.5 小時 / 11 小時 / 2 天 / 6.9 天`
成熟卡（S=40）：`2 天 / 23 天 / 1.7 個月 / 3 個月`

## 3. 卡片從哪來：兩種來源

### 概念卡（concept）
寫在 `node.json` 的 `cards` 陣列，隨課程一起版控。目前 4 節課共 **12 張**：
L0.01（編譯四階段）、L1.02（整數除法）、L1.03（vector/size_t）、L1.05（const/參考）。

**只為「已解鎖」的節點建卡**。這是刻意的：讓你複習還沒讀過的課，只會逼你按「忘記了」，
反而污染排程。冷啟動時只有 L0.01 的 3 張；通過一節、解鎖下一節後才補上。

### 錯誤卡（error）—— 這才是差異化
每次評測失敗，命中錯誤圖鑑的條目會自動變成一張卡：

```
正面：你遇到過：error: expected ';' before '}' token
背面：**少了分號**（編譯階段）
      編譯器讀到 `}` 時發現上一個敘述句沒有結束…
      怎麼修：
      - 看訊息指的那一行，以及它的前一行
      - …
```

同一條錯誤只會有一張卡（`source` 唯一鍵），所以**重複犯錯是累積複習記錄，不是長出新卡**。

> 你練的不是別人的重點，而是**你自己犯過的錯**。

## 4. 驗證證據

| 驗證 | 方法 | 結果 |
|---|---|---|
| 遺忘曲線 | `R(0)=1`、`R(S)=0.9`、單調遞減 | **PASS** |
| 四個按鈕單調 | again < hard < good < easy | **0.11 < 0.46 < 2.00 < 6.88 天** |
| 難度影響 | 同評分下低難度間隔更長 | **29.8d > 22.2d** |
| 穩定度成長 | 每次都在到期日複習 | **2.0 → 2.8 → 4.0 → 5.7 → 8.0 天** |
| 忘記的懲罰 | S=40 按「忘記了」 | **40 → 6 天**，間隔拉回 1.6 天 |
| 邊界 | 100 次混合評分後檢查 | 穩定度有限、難度 ∈ [1,10]、間隔 ∈ (0,365] |
| API | 冷啟動 / 評分 / 踩錯生成錯誤卡 | 3 張 → 評分 200 → 錯誤卡 1 張 ✅ |
| UI 端到端 | `dom-smoke --run` 走完複習流程 | **28/28** |
| 內容 CI | 卡片欄位完整性（q/a） | 10 節點 0 問題 |

### 測試抓到的兩個真問題

1. **穩定度完全不成長**：測試在第一輪就立刻複習（R=1），數學上正確（
   `exp(1.5*(1-1))-1 = 0`）但實務上荒謬。修法有兩個：測試改成模擬「到期才複習」，
   並確認成長曲線合理。
2. **四個按鈕的間隔幾乎一樣**：只差幾個百分點，按鈕形同失效。改成用目標記住機率推導（§2）。

這兩個都不是「程式碼寫錯」，而是**模型設計錯**——只有把數字印出來看才會發現。
